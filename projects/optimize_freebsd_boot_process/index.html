Optimizing the FreeBSD Boot Process

Lahiru Gunathilake. August 24, 2025

Optimizing the boot process of FreeBSD came up as a Google Summer of Code Project in 2025. This project has been supervised by Colin Percival and Toomas Soome. The optimization was approached by first gaining the fundamental understanding of the boot process of FreeBSD operating system by going through the system documentation from the FreeBSD Boot Time wiki and the paper Profiling the FreeBSD Boot Process. This helped to establish an initial perspective on how the boot process sequence is structured and where delays are typically encountered.

In the first stage FreeBSD was installed on a Virtual Box virtual machine. After that the FreeBSD source code was cloned from https://git.freebsd.org/src.git into /usr/src directory. Then, a seperate configuration named BOOT_PROF was created by inheriting the GENERIC profile by enabling the option TSLOG in /usr/src/sys/amd64/conf/BOOT_PROF. 

include GENERIC

# Boot profiling
options		TSLOG

Then the kernel was built and installed. The profiling tools available at freebsd-boot-profiling were then utilized to generate flamecharts to identify the bottlenecks in the system. 

sh mkflame.sh > tslog.svg

Execution of the above produced the first flame chart of the FreeBSD boot sequence. For data transfer, images were shared with remote systems either by piping output through curl into dpaste.com or by installing and enabling a desktop environment on FreeBSD.

Initial Findings in the Virtual Machine Environment

The initial flame chart revealed that BIOS time was reported as excessively long (5055574 ms ~ 1.4 hrs). This behavior was attributed to the virtualized environment, where CPU time is obtained from the host operating system and not reset at the moment the virtual machine is powered on.

Initial flamechart generated in VM (1.4hrs)

However the preliminary analysis highlighted several areas where boot delays could potentially be reduced:

  • IPv6 delay reduction
  • Sleep call investigation
  • Clock calibration optimization
  • Network configuration optimization
  • Device probe delay reduction

The clock calibrarion took additional time because it was running on a Virtual machine and it wasn't appeared in the physical device.

Initial flamechart generated in VM (42s boot time with 8.2 kernel initialization time)

The flame chart produced under this environment exposed the following critical delays:

  • DEVICE_ATTACH atkbd and DEVICE_ATTACH psm (keyboard and mouse initialization)
  • SYSINIT zfsctrlmodule
  • Waits in vfs_mountroot

Optimization Efforts

ZFS Initialization

The checksum initialization in zfs_kmod_init was identified as a bottleneck. Benchmarking was being performed with a 16 MB data set, which caused unnecessary overhead. This was reduced to 256 KB, resulting in a substantial performance improvement. The issue was discussed with the OpenZFS developers and resolved upstream (OpenZFS issue #17560).

Keyboard and Mouse Initialization

Delays were observed in the atkbd_attach routine, specifically within the empty_both_buffers and reset_aux_dev functions. These routines contained wait loops originally intended to accommodate older, slower hardware. Modern devices no longer require such long delays. By reducing these wait times, the initialization of keyboard and mouse devices was significantly improved.

Root Filesystem Mount (vfs_mountroot)

Investigation into the waits occurring in vfs_mountroot revealed that no feasible optimizations were possible within this subsystem.

Results

The optimizations applied to ZFS initialization and keyboard attachment yielded a measurable improvement in boot performance. Device attachment, ZFS initialization, and input device setup were confirmed as the principal sources of delay within the kernel. With these bottlenecks addressed, focus can now be shifted toward userland optimizations in future work.

Conclusion

Through kernel-level profiling and analysis, several inefficiencies in the FreeBSD boot process were identified and addressed. Significant gains were achieved by reducing unnecessary waits in input device initialization and by optimizing checksum benchmarking in ZFS initialization. While certain delays such as those in vfs_mountroot remain unavoidable, the applied improvements represent meaningful progress toward faster and more efficient FreeBSD boot performance.
